# 需求整理

目标：开画之前，把输入整理成三张表，并把所有不确定项一次问清。

- **器件表**：位号、器件类别或型号、值、封装要求、极性方向，以及每一项的状态。
- **网络表**：每个网络连接了哪些“位号.引脚”。
- **版面表**（仅图片输入）：见 `layout-fidelity.md`。

每一项标为 `已确认`、`待确认` 或 `无法识别`。与当前步骤相关的 `待确认`、`无法识别` 项清零之前，不画对应部分。

## 开工前需求清单

信息不全时，只列出仍缺的项，一次发给用户；用户已经给出的不要重复问。

```text
1. 任务：新建 / 图片复刻 / 修改已有工程
2. 工程名，或需要打开的工程路径
3. 只画原理图，还是继续完成 PCB
4. 元件偏好：贴片还是通孔；是否打算用嘉立创下单或贴片；对基础库、库存、价格有无要求
5. （做 PCB）板框尺寸、层数、安装孔、接口位置；线宽、间距有无要求及依据
6. （图片）按图严格复刻（默认），还是只要求电气一致
7. （修改已有工程）当前未保存改动是否保留；是否允许先备份
```

用户说“你看着办”的项：不影响电气正确性和下单结果的（图纸大小、网络标签命名风格等）可以自行决定，在报告里说明；影响电气、封装或下单的仍要确认。

## 读图

1. 先通览整张图：数页数、划分区域（电源、核心芯片、外围、接口等），确认图中是导线连接还是网络标签连接。
2. 逐区放大记录可见事实：器件外形、位号、型号、数值、引脚编号、极性符号、网络标签和电源标识、连接点。
3. 交叉与接点的判读：
   - 清楚可见的实心圆点：连接。
   - T 形接点（一条线终止在另一条线上）：连接。
   - 十字交叉且没有圆点：不连接。
   - 圆点看不清、画法不规范、手绘线端是否碰到引脚看不清：列为 `待确认` 并提问，不按任一默认处理。
4. 放大造成的插值模糊不算看清。不借周围拓扑、“常见电路”或器件概率替用户决定型号和连接。
5. 实物 PCB 照片只能作为补充证据，不能单独用来恢复原理图。

## 文字描述

把描述整理成器件表和网络表。只追问会改变电气正确性或后续 PCB 的缺失项。电路需要计算参数（阻值、功耗、额定值）时，只用已确认的输入和可追溯的公式，并在报告中写出计算依据。

文字输入没有参考版面，原理图按常规画法摆放：信号从左到右，电源在上、地在下，按功能块分组。用户另有要求时按用户的来。

## 提问格式

同一轮发现的问题合并为一份编号清单：

```text
1. 位置：<页码 / 区域 / 位号 / 相邻器件>
   看得清的：<可靠可辨的文字或连接>
   可能是：<有候选时列出，没有不硬凑>
   请补充：<完整型号、数值、清晰局部图，或“相连还是只是交叉”>
   影响：<器件选择、封装、网络、版面或 PCB>
```

用户仍无法确认时保持未解决状态。只有用户明确同意，才放占位器件，并在报告中列出。

## 修改已有工程

- 直接修改用户指定的工程，只动请求涉及的对象；操作前记录目标对象及原值。
- 首次保存或首次更新 PCB 之前，询问是否先备份：只复制整个工程文件，不打开、不改写内部结构；备份放在原工程旁，文件名带 `_pre-edit` 或时间。环境不能复制文件时请用户手动复制。用户拒绝时说明风险后继续。
- 打开时已有来源不明的未保存改动：先问用户如何处理；修改请求本身不等于允许覆盖或保存这些改动。
