# operating-jlceda-pro 问题修复记录

测试日期：2026-10-03。

## 修复依据

本轮不是凭空增加限制，而是把首轮真实客户端验收中已经出现的问题转成回归场景：

- 属性面板偶尔返回上一个器件的数据；
- PCB 封装、供应商封装和 3D 模型互相矛盾；
- 原理图属性同步后已有 PCB 走线被清除；
- 工程从中间观察到的目录形态变为最终单个 `.eprj2` 文件；
- 原理图规则检查在 V4.1.60 中实际显示为 `检查DRC`；
- 当前规则集 DRC 为零，但制造、电气和机械约束并未全部核实。

对应场景为 `JL-STALE-01`、`JL-LIB-01`、`JL-SYNC-01`、`JL-PATH-01`、`JL-TERM-01` 和 `JL-READY-01`。

## RED

```text
FAIL: 关键属性连续两次稳定读取
FAIL: 工程路径以重开后的最终状态为准
FAIL: 原理图保留客户端实际检查名称
FAIL: 库冲突拆分核验
FAIL: PCB 同步前后比较
FAIL: 非预期清线必须停止
FAIL: 区分编辑验收与生产就绪

```

这证明风险虽然已写入复盘，但当时尚未全部成为 Skill 的强制规则。

## GREEN

修改后再次运行同一脚本，结果为 `8/8` 通过。对应规则现在要求：

- 关键属性连同对象身份连续两次观察一致；
- 保存路径以客户端关闭并重新打开后的最终状态为准；
- 原理图规则检查保留客户端实际标签；
- 库冲突按电气身份、引脚映射、PCB 封装、供应商属性和 3D 模型拆分核验；
- PCB 同步前后进行差异比较，非预期清线时停下并请求授权；
- 最终报告区分“编辑验收通过”和“生产就绪已验证”。

本轮 GREEN 是文档契约检查，不伪装成新的独立 Agent 行为测试。原有十次独立行为测试仍记录在 `tests/results.md`；新增六个行为场景留作下一轮独立上下文回归。
